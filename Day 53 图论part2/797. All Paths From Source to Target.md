# 797. All Paths From Source to Target

> [LeetCode 797 链接](https://leetcode.com/problems/all-paths-from-source-to-target/)
>
> 给定一个有 `n` 个节点的有向无环图（DAG），节点编号 `0` 到 `n - 1`，找出所有从节点 `0` 到节点 `n - 1` 的路径。
>
> 图以邻接表形式给出：`graph[i]` 是从节点 `i` 出发能直接到达的所有节点的列表。

## 一、题目本质：DFS 入门 + 图论起点

这道题是**代码随想录图论章节的入门题**。表面是"找路径"，本质考察两件事：

1. 如何读懂**邻接表**这种图的存储方式
2. 如何用 **DFS + 回溯**遍历图上所有路径

```
Example 1:
graph = [[1,2], [3], [3], []]

读法（关键）：
  graph[0] = [1, 2]   → 从 0 出发能到 1、2
  graph[1] = [3]      → 从 1 出发能到 3
  graph[2] = [3]      → 从 2 出发能到 3
  graph[3] = []       → 从 3 出发哪也去不了

图结构：
        1 ──┐
       ↗     ↘
      0       3
       ↘     ↗
        2 ──┘

输出：[[0,1,3], [0,2,3]]
```

## 二、DFS 与回溯的关系

**DFS 是搜索策略，回溯是 DFS 在退回时的"撤销"动作。** 凡是 `做选择 → 递归 → 撤销` 结构的，本质都是 DFS：

| 场景 | "图" 长什么样 | 节点 | 边 |
|---|---|---|---|
| 本题（显式图） | 题目给 `graph[i]` | 节点编号 | 邻接关系 |
| Subsets / Permutations | 隐式决策树 | 当前部分解 | "选 / 不选" |
| 二叉树前序遍历 | 二叉树本身 | TreeNode | 左右子指针 |
| 岛屿数量、单词搜索 | 网格地图 | 格子 (i, j) | 上下左右四个方向 |

**代码骨架完全相同**，只是"图"的形式不同。

## 三、DFS 三部曲（深搜模板）

```java
void dfs(参数) {
    if (终止条件) {
        收集结果;
        return;
    }
    for (选择 : 当前节点的所有邻居) {
        做选择;             // path.add(next)
        dfs(新状态);        // 递归往下
        撤销选择;           // path.remove(last) ← 回溯
    }
}
```

**三步走**：

1. **确认递归函数参数**：通常是 `图、当前节点 x、终点 end`；`result`、`path` 设为全局变量避免参数爆炸
2. **确认终止条件**：到达目标节点 → 收集 `path` → return
3. **处理当前节点的所有出边**：for 循环遍历邻居，做"加 → 递归 → 减"三件套

## 四、解题代码

```java
class Solution {
    List<List<Integer>> result = new ArrayList<>();
    List<Integer> path = new ArrayList<>();

    public List<List<Integer>> allPathsSourceTarget(int[][] graph) {
        path.add(0);                          // 起点 0 先种进 path
        dfs(graph, 0, graph.length - 1);      // 终点是 n - 1
        return result;
    }

    private void dfs(int[][] graph, int x, int end) {
        // 终止条件：到达终点
        if (x == end) {
            result.add(new ArrayList<>(path));  // 注意拷贝!
            return;
        }
        // 遍历 x 的所有邻居
        for (int next : graph[x]) {
            path.add(next);                    // 做选择
            dfs(graph, next, end);             // 递归
            path.remove(path.size() - 1);      // 回溯：撤销
        }
    }
}
```

## 五、Example 1 的 DFS 执行流程

以 `graph = [[1,2], [3], [3], []]` 为例，按调用栈逐步展开：

```
调用前：path.add(0)             →  path = [0]

dfs(0, 3):                       x=0, path=[0]
  x != 3, 遍历 graph[0] = [1,2]
  ├─ next=1: path.add(1)         →  path=[0,1]
  │  dfs(1, 3):                  x=1, path=[0,1]
  │    x != 3, 遍历 graph[1]=[3]
  │    └─ next=3: path.add(3)    →  path=[0,1,3]
  │       dfs(3, 3):             x=3, path=[0,1,3]
  │         x == 3, 收集结果 ✓   →  result=[[0,1,3]]
  │       path.remove()          →  path=[0,1]   ← 回溯
  │  path.remove()               →  path=[0]     ← 回溯
  └─ next=2: path.add(2)         →  path=[0,2]
     dfs(2, 3):                  x=2, path=[0,2]
       x != 3, 遍历 graph[2]=[3]
       └─ next=3: path.add(3)    →  path=[0,2,3]
          dfs(3, 3):             x=3, path=[0,2,3]
            x == 3, 收集结果 ✓   →  result=[[0,1,3],[0,2,3]]
          path.remove()          →  path=[0,2]   ← 回溯
     path.remove()               →  path=[0]     ← 回溯

返回 result = [[0,1,3], [0,2,3]]
```

## 六、易错点

**坑 1：必须拷贝 path**

```java
result.add(path);                    // ✗ 错误：存的是引用
result.add(new ArrayList<>(path));   // ✓ 正确：存快照
```

`path` 是引用对象，直接 add 进去后续 `path.remove()` 会把已收集的结果也改掉。**这和 subsets、permutations 是同一个坑**。

**坑 2：起点何时加入 path**

我们的 `dfs` 函数职责是"加邻居"，所以**起点必须由调用方先加进去**：

```java
path.add(0);          // 调用方负责放起点
dfs(graph, 0, n-1);   // dfs 内只负责加邻居
```

也可以改为在 `dfs` 入口加 `path.add(x)`，但那样 `dfs` 返回前也要 `path.remove`，写法对称但稍微多绕。

**坑 3：要不要 visited 数组**

本题是 **DAG（有向无环图）**，不会有环 → **不需要** `visited`。

但如果图有环（无向图，或有环有向图），必须加 `boolean[] visited`：

```java
visited[next] = true;
path.add(next);
dfs(...);
path.remove(...);
visited[next] = false;   // 回溯时也要取消标记
```

注意这和"岛屿问题"不同——岛屿是"染色一次永久标记"，找路径是"用完归还"。

**坑 4：递归返回后的代码什么时候执行**

```java
path.add(next);                    
dfs(graph, next, end);             // ← 这里返回后
path.remove(path.size() - 1);      // ← 立即执行这一行
```

每次 `dfs(...)` 返回，控制流就回到调用它的那一层，下一行 `path.remove` 立即执行。**这就是回溯的本质**：每次 `add` 都对应一次 `remove`，无论递归调用里发生了什么，回来之后必撤销。

## 七、复杂度分析

- **时间复杂度**：`O(2^n × n)`。最坏情况图是完全 DAG，路径数指数级，每条路径长度最多 n
- **空间复杂度**：`O(n)`，递归栈深度 + path 长度，均不超过 n（不计 result 本身）

## 八、心智模型：笔与拍照本

- `path` 是**一支正在探索的笔**：
  - `path.add(x)` = 笔尖往前走一步
  - `dfs(...)` = 沿着这一步继续探索
  - `path.remove(...)` = 笔尖往回缩一步
- `result` 是**拍照本**：每到达终点就拍一张照（`new ArrayList<>(path)`），保存的是那一瞬间的快照，之后笔尖怎么动都不影响

## 九、总结

1. **DFS 的本质是"一条路走到黑，走不通再回头"**，回头的动作就是回溯
2. **DFS 三部曲**：确认参数 → 确认终止条件 → 处理当前节点的所有出边（加 → 递归 → 减）
3. **图论 DFS 与回溯决策树的代码骨架完全一样**，只是"图"的形式不同（显式邻接表 vs 隐式决策树）
4. **`result.add(new ArrayList<>(path))`** —— 收集结果时必须拷贝，这是所有"收集所有方案"类题目的统一坑点
5. **DAG 不需要 visited，普通图需要**，且回溯时要取消标记
6. **后续衔接**：图论 DFS 还会扩展到环检测、连通分量、网格搜索（岛屿问题、单词搜索）等场景
