# 496. 下一个更大元素 I

> [LeetCode 496. Next Greater Element I](https://leetcode.com/problems/next-greater-element-i/)

`nums1` 是 `nums2` 的子集，对 `nums1` 中的每个元素 `x`，在 `nums2` 中找到 `x` 之后**第一个比 x 大**的元素，找不到返回 `-1`。

## 核心思路

**反向思考**：不要在 `nums1` 里找 `nums2`，而是**先用单调栈处理 `nums2`，把每个元素的"下一个更大元素"存入 HashMap**，再让 `nums1` 直接查表。

因为 `nums1` 是 `nums2` 的子集，所以 `nums2` 里每个数的答案 = `nums1` 里对应数的答案。

**关键决策**：
- **栈里存"值"而不是"下标"**：最终要用值去 HashMap 里查，存值最直接（区别于 Daily Temperatures 那种需要算距离的题）
- **单调递减栈**：栈底 → 栈顶 递减。一旦来个更大的数，就能弹出栈顶并记录答案
- **HashMap 兜底**：栈里剩下的元素没有"下一个更大元素"，用 `getOrDefault(key, -1)` 优雅处理

## 解题步骤

### 1. 用单调栈预处理 nums2

维护一个**单调递减栈**，遍历 `nums2`：当遇到一个比栈顶大的数时，栈顶元素的"下一个更大元素"就是当前数 → 存入 HashMap。

```java
Map<Integer, Integer> map = new HashMap<>();
Deque<Integer> stack = new ArrayDeque<>();  // 单调递减栈，存"值"

for (int num : nums2) {
    while (!stack.isEmpty() && num > stack.peek()) {
        map.put(stack.pop(), num);
    }
    stack.push(num);
}
```

### 2. 遍历 nums1 查表

```java
int[] res = new int[nums1.length];
for (int i = 0; i < nums1.length; i++) {
    res[i] = map.getOrDefault(nums1[i], -1);
}
return res;
```

## 完整代码

```java
class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map<Integer, Integer> map = new HashMap<>();
        Deque<Integer> stack = new ArrayDeque<>();

        // 1. 单调栈处理 nums2,记录每个元素的下一个更大元素
        for (int num : nums2) {
            while (!stack.isEmpty() && num > stack.peek()) {
                map.put(stack.pop(), num);
            }
            stack.push(num);
        }

        // 2. nums1 直接查表
        int[] res = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) {
            res[i] = map.getOrDefault(nums1[i], -1);
        }
        return res;
    }
}
```

## 示例走一遍

```
nums2 = [1, 3, 4, 2], nums1 = [4, 1, 2]
```

**遍历 nums2**：

| 当前 num | 操作 | 栈状态 | map 状态 |
|---------|------|--------|----------|
| 1 | 栈空，push | `[1]` | `{}` |
| 3 | 3>1，pop 1 记录 → push 3 | `[3]` | `{1→3}` |
| 4 | 4>3，pop 3 记录 → push 4 | `[4]` | `{1→3, 3→4}` |
| 2 | 2<4，push | `[4, 2]` | `{1→3, 3→4}` |

栈中剩余的 `4` 和 `2` 没有下一个更大元素，跳过。

**查 nums1**：
- `nums1[0]=4` → map 无 → `-1`
- `nums1[1]=1` → `map[1]=3` → `3`
- `nums1[2]=2` → map 无 → `-1`

**结果**：`[-1, 3, -1]`

## 复杂度分析

- **时间复杂度**：`O(n + m)`，其中 `n = nums2.length`，`m = nums1.length`。每个元素最多入栈、出栈一次。
- **空间复杂度**：`O(n)`，HashMap 和栈最多存 `n` 个元素。

## 总结

1. **反向预处理**：题目让你为 `nums1` 找答案，但更高效的做法是先为 `nums2` 全员算好答案，存入 HashMap
2. **单调递减栈**是求"下一个更大元素"的标准套路
3. **栈存值还是存下标**取决于最终要用什么：
   - 要查值 → 存值（本题）
   - 要算距离 → 存下标（Daily Temperatures）
4. **暴力解法** `O(n×m)` 双层循环也能 AC，但完全浪费了单调栈一次遍历搞定的优势
5. **同类题套路**：遇到"子集 + 下一个更大/更小元素"的组合题，优先想"预处理全集 + HashMap 查表"
